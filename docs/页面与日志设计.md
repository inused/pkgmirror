# pkgmirror 页面导航、列表搜索与服务端日志设计

> 服务端页面的三项改进：导航按编程语言分组重组（语言本体在前、包仓库
> 在后）、列表页内嵌模糊搜索（uFuzzy，前端过滤）、文件下载与缺失日志
> （含反代场景的来源 IP）。零新增第三方 Go 依赖，uFuzzy 以
> go:embed 内嵌进二进制，保持单文件离线交付。

## 1. 目标与范围

1. 导航与首页统计按语言分组排序：Python 组（安装包 → PyPI 包）、
   Node.js 组（npm 包），消除"包排在语言前"的别扭顺序；
2. PyPI 包、npm 包、Python 安装包三个列表页支持输入即时模糊过滤；
3. 服务端记录文件下载成功、404 缺失、上传成功三类日志，带来源 IP，
   覆盖反代部署场景。

不做：后端搜索 API、跨镜像联合搜索、全站 access log（浏览页、simple
索引、packument 协议请求均不记录）、请求频率统计。

## 2. 导航分组

成熟经验参照：TUNA/USTC 综合站条目数百、平铺字母序，量级不同不可参考；
阿里云镜像站有"语言"分组。本项目仅 3 类内容，按语言分组表达归属关系。

```
调整前：pkgmirror | 首页 | PyPI 包 | Python 安装包 | npm 包 | 上传
调整后：pkgmirror | 首页 | Python ▸ 安装包 · PyPI 包 | Node.js ▸ npm 包 | 上传
```

- 组名"Python"、"Node.js"复用 `nav b` 灰色小字样式，纯横向布局、
  无下拉菜单，兼容性不变；
- 首页统计卡片顺序同步调整为：Python 构建标签 → PyPI 包 → npm 包；
- 后续扩展（如 node/ 语言本体）在 Node.js 组内加链接即可，与 Python
  组结构对称。

### 2.1 全站排序约定（2026-10 修订）

页面、help 与文档中同一处出现多种语言的内容时，统一按以下规则排序：

1. 语言分组顺序固定：Python → Node.js → Go，组间不允许交错；
2. 组内顺序按语境二选一：
   - **页面浏览类**（导航、首页统计、浏览路由表、download 类型枚举）：
     语言本体（安装包）在前、包仓库在后——先有语言本体再装包；
   - **接入配置类**（首页接入配置块、协议路由表、README 接入示例）：
     包接入（索引 / registry / GOPROXY）在前、本体接入（版本管理器）在
     后——装包是主用途；
3. 例外：上传表单 type 下拉以最高频手工上传场景（自研 pypi wheel）为
   首项；delete 帮助按删除单位参数形态（包名 / 版本号）分两行列出。

## 3. 列表页模糊搜索

### 3.1 方案：前端过滤

列表页本就全量渲染（ReadDir 列出全部包名），搜索只是对已下发数据做
过滤，前端方案零后端改动、输入即时反馈；离线内网包数量在几十至几千级，
无性能压力。后端搜索仅在万级数据 + 分页场景才成立，当前不适用。

### 3.2 库选型：uFuzzy

| 候选 | 体积(min) | 性能 | 维护 | 结论 |
| --- | --- | --- | --- | --- |
| uFuzzy v1.0.19 | 8.4KB（gz ~5KB） | 短词 × 大列表场景最强 | 活跃（uPlot 作者） | 采用 |
| Fuse.js | ~7KB(gz) | 评分算法较重 | 活跃 | 备选，未采用 |
| fuzzysort | ~9KB | 强 | 仓库已归档 | 排除 |

uFuzzy 的设计目标即"短查询词匹配大列表短语"，排序接近编辑器体验
（前缀 > 连续 > 分散），零依赖单文件，语法 ES2018 以内，满足
Chrome 89 基线。

### 3.3 引入方式与行为

- 单文件 iife 版存放 `internal/server/static/ufuzzy.min.js`，
  `go:embed` 嵌入二进制，新增路由 `/static/ufuzzy.min.js` 由
  handler 直接输出字节（不挂 FileServer，避免目录遍历面）；
- 三个列表页模板在表格上方加过滤输入框与命中计数 span；
- 共享过滤脚本（模板 const 内嵌）：取每行 `textContent` 小写化为
  候选集，`uFuzzy.filter()` 选中后 `uFuzzy.sort()` 按相关度排序并
  `appendChild` 重排，未命中的行 `display:none`；输入清空则恢复
  原序（先记录初始行序，恢复时按原序 appendChild）；
- 命中计数显示"命中 N 项"或"无匹配项"；
- JS 不可用时列表仍完整可见，仅过滤失效（搜索框不隐藏，Chrome 89
  基线下无此场景）；
- 搜索脚本与 uFuzzy 引用仅在三个列表页模板输出，详情页不涉及。

## 4. 服务端访问日志

### 4.1 埋点清单

| 事件 | 位置 | 格式示例 |
| --- | --- | --- |
| 下载 | pypi 文件、python 安装包、npm 文件（含 packument.json 原始文件下载）成功 | `下载 ip=192.168.1.10 GET /pypi/requests/requests-2.34.2-py3-none-any.whl 200 356.2K` |
| 缺失 | 上述三类 handler 的 404 分支（含白名单拒绝） | `缺失 ip=192.168.1.10 GET /npm/lodash/-/lodash-4.17.21.tgz 404 0B` |
| 已接收 | storeUpload 成功落盘（现有日志补 ip 字段） | `已接收 ip=192.168.1.10 npm/lodash/lodash-4.17.21.tgz (sha256=abc123)` |

不记录：浏览页面、simple 索引、packument 协议请求（`/npm/{name}` 无
`/-/` 段）——pip/npm 正常安装高频拉取，记录会刷屏且排障信息量低；谁在
用、缺什么，看下载与缺失日志已足够。packument 的 404 走 npmNotFound，
仍记缺失（缺包是离线镜像最常见故障）。

### 4.2 来源 IP

`clientIP(r)` 按优先级取：

1. `X-Forwarded-For` 首段（逗号分隔链的最左一段，即链路最原始客户端）；
2. `X-Real-IP`（nginx 惯例头）；
3. `RemoteAddr` 去端口。

XFF/X-Real-IP 可被客户端伪造，仅在"直连或可信反代"部署下准确；该 IP
只用于排障定位，不作访问控制依据。

### 4.3 大小字段

用现有 `humanSize` 输出（`356.2K`、`512B`），便于人工扫读；404 记
`0B`，日志字段顺序固定，方便 grep。

## 5. 验收与验证

- 单元测试：clientIP 的 XFF 多段/单段、X-Real-IP、RemoteAddr 兜底；
  下载与缺失日志内容断言（log 缓冲捕获）；上传日志含 ip；导航分组
  顺序断言（Python 链接位于 PyPI 之前）；三个列表页含过滤框与
  uFuzzy 脚本引用；`/static/ufuzzy.min.js` 返回 200 与完整字节；
- 人工冒烟：`go run . server` 后核对导航布局、过滤交互（含排序、
  清空恢复、无匹配提示）、XFF 反代场景日志；
- `go test ./...` 全量通过，四平台交叉编译通过。
