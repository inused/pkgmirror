# pkgmirror 路由设计

## URL 用途

`/browse/*` 提供浏览页面，`/mirror/*` 提供镜像协议响应与文件。浏览路径按镜像类型分层，例如 PyPI 包 `npm` 的详情页为 `/browse/pypi/npm/`，与 npm 包列表 `/browse/npm/` 区分。

首页位于 `/`，上传页面位于 `/upload`，上传和删除接口分别位于 `/api/upload`、`/api/delete`，内嵌搜索库位于 `/static/ufuzzy.min.js`。全部路由经过 Basic auth 中间件。

## URL 布局

浏览路径的类型名与存储目录名一致：

| 路径 | 内容 |
| --- | --- |
| `/browse/pypi/`、`/browse/pypi/{name}/` | PyPI 包列表/详情 |
| `/browse/npm/`、`/browse/npm/{name}/` | npm 包列表/详情 |
| `/browse/gomod/`、`/browse/gomod/{module}/` | Go 模块列表/详情（模块路径含多段斜杠，取 `gomod/` 后全部） |
| `/browse/python/`、`/browse/node/`、`/browse/golang/` | 安装包列表 |

镜像协议路径：

| 路径 | 客户端 |
| --- | --- |
| `/mirror/simple/{name}/`、`/mirror/simple/` | pip / uv（PEP 503） |
| `/mirror/pypi/{name}/{file}` | 包文件下载（simple 页与详情页的 href） |
| `/mirror/npm/{name}`、`/mirror/npm/{name}/-/{file}` | npm registry |
| `/mirror/python/{tag}/{file}`、`/mirror/node/{version}/{file}`、`/mirror/golang/{file}` | uv / nvm / mise / asdf |
| `/mirror/goproxy/...` | go module proxy |

`simple` 与 `pypi` 共用 `pypi/` 存储目录，分别提供索引和文件下载；`goproxy` 对应 `gomod/` 存储目录。

## 路径解析与响应

- `Server.Handler` 注册路由，`handleBrowse` 按六种镜像类型分发浏览请求。
- PyPI simple 索引中的文件链接指向 `/mirror/pypi/`；npm packument 中的 tarball 地址在请求时重写为 `/mirror/npm/` 下的本机地址。
- npm scoped 包与 Go 模块路径通过 `EscapedPath` 和 `PathUnescape` 解析，保留编码斜杠的含义。
- `/mirror/simple/` 返回包索引；npm、Python、Node、Go 安装包的协议根，以及安装包目录层返回 404。`/browse/` 裸根也返回 404。
- 未知路径和缺失文件返回 404；文件缺失提示页提供补下载命令和对应浏览页链接。

## 验证

`internal/server/server_test.go` 覆盖浏览页、协议响应、文件链接、路径校验及缺失响应，`delete_test.go` 覆盖页面删除流程。运行 `go test ./...` 和 `go build ./...` 检查。
