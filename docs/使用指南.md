# pkgmirror 使用指南

本文是详细使用说明。架构与协议设计见 [设计.md](设计.md)、[npm设计.md](npm设计.md)，
快速上手见 [项目 README](../README.md)。

## 构建

```bash
go build -o pkgmirror .      # 当前平台
scripts/build.sh            # macOS/Linux：交叉编译四平台产物到 dist/
scripts\build.bat           # Windows：同上
```

产物：pkgmirror-windows-amd64.exe（Go 1.20.7 保证 Windows 7 可运行）、
pkgmirror-linux-amd64、pkgmirror-linux-arm64（CGO 禁用，静态链接）、
pkgmirror-darwin-arm64。构建脚本会附带示例配置到 dist/。

## 服务端

### 启动与配置

```bash
cp resources/server.example.toml server.toml   # 按需修改
./pkgmirror server --config server.toml
```

配置项：

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `listen` | `":19999"` | 监听地址 |
| `root` | `"./data"` | 数据根目录（相对路径**相对配置文件所在目录**解析，见下） |
| `[users]` | 空 | Basic auth 用户表；空表不启用认证（任何人可访问和上传） |

未找到配置文件时按默认值启动并在日志中提示。

**默认路径的探测规则（便携部署）**：

- `--config` 缺省时依次探测 `./server.toml` → 二进制同目录的
  `server.toml`，先命中先用；两处都没有按无配置启动。从任意目录启动、
  双击运行、systemd 托管（CWD 不可控）时都能找到随身配置；
- `root` 为相对路径时相对**配置文件所在目录**解析（配置在哪数据跟在哪）；
  无配置文件时相对二进制目录。启动日志打印解析后的绝对数据目录；
- 客户端 `--config` 对 `client.toml` 用同样的探测链；`-o downloads`
  产出目录仍相对当前目录（在哪执行产出在哪）。

### 数据目录

```
data/
├── pypi/      PyPI 包：{规范包名}/{name}-{version}-*.whl|.tar.gz|.zip
├── python/    Python 安装包：{构建tag}/cpython-...-install_only*.tar.gz
└── npm/       npm 包：{包名，scoped 为 @scope/name/}/packument.json + {name}-{version}.tgz
```

顶层每个子目录是一种镜像类型，扩展新镜像类型时平铺新增。simple 索引
每次请求实时扫描目录，无索引缓存；包文件的 sha256 缓存在同名 `.sha256`
文件中（首次访问自动生成）。

### 网页功能

导航按编程语言分组（语言本体在前、包仓库在后）：Python 组含安装包与
PyPI 包，Node.js 组含 npm 包。三个列表页支持输入即时模糊过滤（容错
单字符打错，如输 `idn` 命中 `idna`），由内嵌的 uFuzzy 在浏览器端完成。

| 路径 | 功能 |
| --- | --- |
| `/` | 首页：统计、按实际访问地址生成的接入配置（可一键复制） |
| `/browse/` | PyPI 包列表（顶部有 pip/uv 接入说明条，支持模糊过滤） |
| `/browse/{包名}/` | 包内文件列表（文件名、大小、sha256、下载链接） |
| `/python/` | Python 安装包列表（构建标签、版本、文件、大小，支持模糊过滤） |
| `/npm/` | npm 包列表（包名、文件数、大小，支持模糊过滤） |
| `/browse/npm/{包名}/` | npm 包详情（tarball 与 packument 的下载链接、大小、sha256） |
| `/upload` | 手工上传（自研 wheel 等；自动从文件名解析包名，解析失败可手填） |
| `/simple/`、`/simple/{包名}/` | PEP 503 索引（供 pip/uv，非人读） |
| `/npm/{包名}`、`/npm/{包名}/-/{文件}` | npm registry 协议（供 npm/pnpm/yarn，非人读） |

### 访问日志

文件下载成功与 404 缺失各记一条，上传成功补记来源 IP，格式固定便于
grep（IP 依次取 X-Forwarded-For 首段、X-Real-IP、RemoteAddr，兼容反代
部署；转发头可伪造，仅用于排障定位）：

```
下载 ip=192.168.1.10 GET /pypi/requests/requests-2.34.2-py3-none-any.whl 200 356.2K
缺失 ip=192.168.1.10 GET /npm/lodash/-/lodash-4.17.21.tgz 404 0B
已接收 ip=192.168.1.10 npm/lodash/lodash-4.17.21.tgz (sha256=abc123)
```

内网用户报"装不上"时先 grep `缺失`：404 即缺文件，按提示在外网补
下载再上传即可。浏览页面与索引请求不记录（安装过程高频拉取，会刷屏）。

### 上传语义

- 相对地址与文件名走白名单校验，无路径穿越风险；
- 已存在且 sha256 一致：跳过（幂等，可重复上传）；
- 已存在但内容不同：返回 409 拒绝覆盖，需人工删除旧文件；
- 写入采用临时文件 + 原子重命名，中断不会留下半截文件。

## 下载（download）

download 按资源类型分三个子命令（pypi / python / npm），选项写在位置参数
之前或之后均可。所有下载产出到统一目录（默认 `downloads/`，`-o` 换目录），
重复执行时 manifest 与已有条目增量合并、相同文件跳过；目录是累积的，
过滤条件只影响本次新增，需要全新集合时用 `-o` 指定新目录。

### 下载 PyPI 包（download pypi）

```bash
pkgmirror download pypi --python 3.12 six               # 裸包名：取兼容该 Python 的最新版
pkgmirror download pypi --python 3.12 six==1.17.0       # 锁定版本
pkgmirror download pypi --python 3.11,3.12 -r req.in    # 需求文件（每行一个 包名[==版本]）
```

- `--python` 必填：既是 uv 依赖解析的版本下限，也是 wheel 文件过滤条件；
  只下载兼容目标版本的 wheel，纯 Python wheel（`any` 标签）与 sdist 始终保留；
- 依赖解析调用本机的 uv（`uv pip compile --universal`），自动解析全部
  传递依赖，多版本目标下按 uv 的分叉策略各取兼容版本；
- 全部输入写成 `包名==版本` 精确形式时**无需 uv** 直接下载（不解析传递
  依赖，闭包由清单自身保证；内网 lock 清单传出来逐包下载的场景）；
- 依赖解析需要本机安装 uv，未安装时报错并给出安装指引（`pip install uv`）；
- `--platform linux,windows`、`--arch x86_64,aarch64` 过滤 wheel 平台标签。

### 下载 Python 安装包（download python）

```bash
pkgmirror download python 3.12               # 3.12 系列最新补丁版，全平台
pkgmirror download python 3.12.4 3.13.1      # 精确补丁版，多个版本
pkgmirror download python 3.12 --all         # 全部历史补丁版（体积大，慎用）
pkgmirror download python 3.12 --platform linux --arch x86_64
```

默认排除 freethreaded/debug 等构建变体；`--arch` 支持 amd64/arm64 别名。
元数据取自 uv 仓库的下载清单，保证文件名与 uv 请求严格一致。
体积参考：每个补丁版全平台约 1.2~1.5GB。

### 下载 npm 包（download npm）

```bash
pkgmirror download npm lodash                     # 裸包名：npm 取最新版，含全部传递依赖
pkgmirror download npm lodash@^4 @babel/core@^7   # semver range，scoped 包
pkgmirror download npm -r ./package.json          # 项目依赖（dev/optional 全收）
pkgmirror download npm -r ./package-lock.json     # 现成 lock：无需本机 npm，与 lock 版本逐条一致
pkgmirror download npm -r ./package-lock.json --platform windows --arch x86_64
```

- 每个包下载一份 packument（元数据）加锁定版本的 tarball；packument 是
  npm 依赖解析的必需数据，与 tarball 一同镜像；
- 裸包名 / semver range / `-r package.json` 需要外网机装有 npm ≥ 7
  （负责依赖解析）；`-r package-lock.json` 按内容识别后直接解析，
  **无任何外部工具依赖**，且下载版本与 lock 逐条一致（内外网有时间差时，
  解析模式可能解析出更新版本，内网按旧 lock 安装反而缺件，已有 lock 的
  团队优先用本方式）；
- `-r lock` 与命令行包名互斥（lock 是完整闭包）；yarn.lock / pnpm-lock.yaml
  不支持，先在外网机 `npm install --package-lock-only` 转为 package-lock.json；
- git+/file: 依赖逐条警告并跳过（无法经 registry 镜像，需人工处理）；
- `--platform` / `--arch` 过滤 lock 标注 os/cpu 的平台二进制包
  （esbuild、@swc/core 类），无标注的包不受影响；
- `--node 18` / `--node 18,20.1` 校验各包的 engines.node：每个目标版本
  都必须满足，不满足时列出全部违规条目并中止（版本选择不受影响——npm
  无法按目标 node 解析，需人工调整 range 重新解析或升级内网 node）；
  `18` 按 18.0.0 保守校验，engines 要求小版本时给精确 minor（如 18.17）；
  多数包不声明 engines，不受影响；
- npm registry 配置：`--registry` > `client.toml registry` >
  `NPM_CONFIG_REGISTRY` > 官方源。

### 网络配置（三级来源）

命令行参数 > 客户端配置文件 > 环境变量 > 默认值，各配置项独立生效：

| 配置项 | 优先级链 | 默认 |
| --- | --- | --- |
| PyPI 索引 | `--index-url` > `client.toml` > `UV_INDEX_URL` > `PIP_INDEX_URL` > pip.conf | 官方源 |
| npm registry | `--registry` > `client.toml` > `NPM_CONFIG_REGISTRY` | 官方源 |
| GitHub 反代 | `--github-prefix` > `client.toml` > `GITHUB_PREFIX` | 直连 |
| HTTP 代理 | `--proxy` > `client.toml` > `HTTP_PROXY`/`HTTPS_PROXY` | 直连 |

客户端配置文件默认探测当前目录 `client.toml`，模板见
`resources/client.example.toml`。上传（upload）目标为服务端地址，
显式禁用代理，不受上述代理配置影响。

各子命令较长的选项均有等价短参数（如 `--config`/`-c`、`--platform`/`-p`、
`--index-url`/`-i`、`--registry`/`-R`、`--github-prefix`/`-g`、`--proxy`/`-x`、
`--python`/`-P`、`--server`/`-s`），长短参数对应同一实际参数，选项写在位置参数
前后均可，完整对应见各层 `-h`。

## 上传（upload）

```bash
pkgmirror upload --server http://user:pass@host:port downloads
pkgmirror upload --server http://host:port --user user --pass pass downloads
```

- 目录缺省为 `downloads/`（download 的默认产出目录）；
- 按 manifest.json 清单逐文件上传并校验 sha256，服务端已有相同文件跳过；
- 任一文件失败继续尝试其余，最后汇总失败清单并以非零退出码结束；
- 凭据可直接嵌在服务端地址里，端口以服务端配置为准。

## 使用方接入

服务端首页会按实际访问地址生成可复制的配置。手动配置：

```bash
# uv（写入 shell 配置文件）
export UV_INDEX_URL=http://user:pass@host:port/simple
export UV_PYTHON_INSTALL_MIRROR=http://user:pass@host:port/python

# pip
pip install --index-url http://user:pass@host:port/simple 包名

# npm / pnpm（写入用户 ~/.npmrc 或项目 .npmrc；npm 不支持 URL 内嵌凭据）
registry=http://host:port/npm/
//host:port/:_auth=BASE64(user:pass)    # echo -n user:pass | base64
```

```yaml
# yarn berry（.yarnrc.yml，取值与上相同）
npmRegistryServer: http://host:port/npm/
npmAuthIdent: BASE64(user:pass)
```

之后 `uv pip install`、`uv python install 3.12`（支持精确补丁如 `3.12.4`）、
`pip install`、`npm install`（及 pnpm / yarn）全部走镜像。项目自带旧
lock 文件时建议内网 npm ≥ 8.3（对指向官方源的 resolved 自动替换为
registry 配置），首次接入也可删除 lock 重新解析（packument 已镜像，
可行）；pnpm 已实测同样按 registry 重新解析、不回源官方，yarn 未实测。

## 常见问题

**uv python install 报 404？**
该安装包未同步到镜像。服务端的 404 页会给出补下载指引；在可联网机器执行
`pkgmirror download python <版本>` 后上传即可。注意使用方 uv 版本不宜过旧——
新发布的 Python 补丁版只有较新的 uv 认识。

**pip install 报找不到包？**
该包未同步。用 `download pypi` 下载后上传；simple 索引只包含已同步的包，
不支持代理回源（这是离线镜像的设计边界）。

**npm install 报找不到包或版本？**
该包（版本）未同步。服务端 404 页有补下载指引；外网执行
`pkgmirror download npm <包名[@range]>` 或 `-r package-lock.json` 后上传。
已镜像的包不会解析出未镜像的版本——内网按 lock 安装时如遇缺件，
直接用该 lock 在外网重新下载即可逐条对齐。

**上传返回 409？**
目标已存在同名但内容不同的文件。确认版本后人工删除旧文件再上传，
工具不自动覆盖。

**Windows 7 能跑吗？**
可以，产物基于 Go 1.20.7（最后支持 Win7 的版本），cmd 下直接运行 exe。

## 扩展新镜像类型

存储（`data/<类型>/`）、下载子命令（`download <类型>`）、页面章节与示例
配置（`resources/<类型>.example.toml`）均按类型平铺组织，扩展时对上述
四处各加一种类型即可，互不冲突。
