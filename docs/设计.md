# pkgmirror 设计

> 单二进制工具：内网 uv/pip 离线镜像服务端 + 外网下载/内网上传客户端。
> Go 1.20.7（最后支持 Windows 7 的版本），纯标准库 + BurntSushi/toml（唯一第三方依赖）。

## 1. 目标与范围

完全内网（无法出网）的 10 人以内团队，需要：

1. 内网服务器提供 PyPI 镜像（PEP 503 simple 协议，pip/uv 通用）；
2. 内网服务器提供 uv 管理的 CPython 安装包镜像（`UV_PYTHON_INSTALL_MIRROR` 协议）；
3. 外网机按需下载指定包和 Python 版本（全平台），经 U 盘等拷贝进内网后一键上传；
4. 内网自研 wheel 可通过网页手工上传；
5. 全程 Basic auth，无任何中间件，数据即文件目录。

不做：PyPI 全量镜像、依赖解析（交外网机的 uv）、pypy/GraalPy 等非 CPython 实现、HTTPS。

## 2. 总体架构

```
外网机                                内网
pkgmirror download                     pkgmirror server（常驻，监听 :19999）
  ├─ uv pip compile --universal  →    ├─ /simple/{name}/    PEP 503（动态扫描 pypi/）
  │  依赖解析（需外网机装 uv）        ├─ /pypi/...          PyPI 包文件下载
  ├─ 从 PyPI simple API 下载          ├─ /python/{tag}/{file} CPython 安装包下载
  ├─ 从 uv 仓库元数据下载             ├─ /api/upload        上传接口（客户端+网页共用）
  │  CPython 安装包                   └─ / /browse/ /python/ /upload  人用页面
  └─ 产出下载产出目录+manifest.json
        │ U 盘拷贝
        ▼
内网任意机 pkgmirror upload <目录> ──POST──> /api/upload
```

## 3. 命令行

```
pkgmirror server  [--config server.toml]
pkgmirror download python <版本>... [--platform linux] [--arch x86_64] [--all]
                            [--github-prefix URL] [--proxy URL] [-o 目录]
pkgmirror download pypi --python 3.11[,3.12] <包名[==版本]>... [-r FILE]
                       [--platform linux,windows] [--arch x86_64,aarch64]
                       [--index-url URL] [--proxy URL] [-o 目录]
pkgmirror upload <下载产出目录> --server http://host:19999 [--user u --pass p]
```

## 4. 服务端

### 4.1 存储布局（root 目录）

```
data/
├── pypi/{规范包名}/{name}-{version}-*.whl|.tar.gz|.zip
├── python/{构建tag}/cpython-...-install_only*.tar.gz
└── （伴随 {文件名}.sha256 缓存，十六进制小写，simple 页面生成时按需计算）
```

- 规范包名按 PEP 503：小写、`[-_.]+` 连续折叠为 `-`；
- 构建标签为 8 位日期数字；
- simple 页面每次请求实时扫描目录，不做索引缓存（10 人规模扫描 <10ms）。

### 4.2 路由（全部经 Basic auth 中间件）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 首页：统计+导航 |
| GET | `/simple/` | PEP 503 根索引（全部包名 anchor） |
| GET | `/simple/{name}/` | 包文件页，href=`/pypi/{name}/{file}#sha256=...` |
| GET | `/pypi/{name}/{file}` | PyPI 包文件下载 |
| GET | `/python/` | Python 安装包浏览列表 |
| GET | `/python/{tag}/{file}` | 安装包下载；404 返回 HTML 提示"文件未同步，请外网执行 download --python x.y" |
| GET | `/browse/`、`/browse/{name}/` | 人用浏览页（包列表/文件列表） |
| GET | `/upload` | 上传表单页 |
| POST | `/api/upload` | 上传接口，multipart 表单 |

simple HTML 为 PEP 503 原生格式（`text/html`），pip/uv 均直接支持。

### 4.3 上传接口（客户端与网页共用）

multipart 表单字段：

| 字段 | 说明 |
| --- | --- |
| `type` | `pypi` 或 `python` |
| `name` | type=pypi 时的包名（客户端已规范化；网页端可留空由服务端从文件名解析） |
| `tag` | type=python 时的构建标签（8 位数字） |
| `sha256` | 调用方提供的期望哈希，服务端落盘前校验（网页上传可留空） |
| `file` | 文件本体 |

处理规则：

- 文件名仅允许 `[A-Za-z0-9._+-]`，拒绝路径分隔符与 `..`；
- type=pypi 落盘 `pypi/{norm(name)}/{filename}`；name 缺失时从文件名解析（首段 `-` 前，规范化），解析失败返回 400；
- type=python 落盘 `python/{tag}/{filename}`；
- 目标已存在：sha256 一致返回 `{"status":"skipped"}`（幂等），不一致返回 409；
- 先写 `.part` 临时文件再 rename，写入成功同步写 `.sha256` 缓存；
- 响应 `{"status":"ok|skipped","path":"..."}`。

### 4.4 认证

- `server.toml` 中 `[users]` 表；空表则不启用认证（启动时日志警告）；
- `Authorization: Basic` 校验，密码比较用恒定时间比较；
- 401 响应带 `WWW-Authenticate: Basic realm="pkgmirror"`；
- 内网用户侧配置示例：`UV_INDEX_URL=http://user:pass@host:19999/simple`、`UV_PYTHON_INSTALL_MIRROR=http://user:pass@host:19999/python`（pip 同理，凭据嵌入 URL）。

### 4.5 配置（server.toml）

```toml
# 监听地址
listen = ":19999"
# 数据根目录（pypi/ 与 python/ 的父目录，每类镜像一个顶层子目录）
root = "./data"

# Basic auth 用户表；留空则不启用认证
[users]
admin = "CHANGE_ME_BEFORE_STARTING"
```

`--config` 指定路径，默认 `./server.toml`；文件不存在时按内置默认值启动并警告。

## 5. 客户端 download

download 按资源类型拆为两个子命令，`--python` 不再跨用途复用：
`download python` 的版本是位置参数（必需）；`download pypi` 的包名是位置参数
（必需带 `==版本`），`--python` 仅在此作为解析与过滤参数（必需）。
选项与位置参数的先后顺序不限（入口处统一重排）。

### 5.1 源与代理选择（三级配置来源）

命令行参数 > 客户端配置文件（`--config` 指定，默认探测 `./client.toml`，
模板见 `resources/client.example.toml`）> 环境变量 > 内置默认，各配置项独立生效：

| 配置项 | 优先级链 | 默认 |
| --- | --- | --- |
| PyPI 索引 | `--index-url` > 配置文件 `index-url` > `UV_INDEX_URL` > `PIP_INDEX_URL` > pip.conf `[global] index-url` | 官方源 |
| GitHub 反代 | `--github-prefix` > 配置文件 `github-prefix` > `GITHUB_PREFIX` | 直连 |
| HTTP 代理 | `--proxy` > 配置文件 `proxy` > `HTTP_PROXY`/`HTTPS_PROXY`（含小写，Go 标准行为） | 直连 |

代理实现：显式代理通过 `http.ProxyURL` 固定到 Transport；未配置时沿用
`http.ProxyFromEnvironment`，因此外网机惯用的代理环境变量零配置生效。
upload 子命令的目标是内网地址，显式禁用代理，避免外网代理环境变量劫持内网请求。

### 5.2 依赖解析（调用外网机的 uv）

- 外网机需安装 uv，未安装则报错退出并给出安装指引；
- 将 `-r` 文件与命令行包名合并为临时 requirements.in；
- 执行 `uv pip compile --universal --no-header --index-url {源} -p {下限} {in} -o {lock}`；
- `--python` 指定的多个版本取最小 minor 作为 `-p` 下限；未指定时默认 `3.9`；
- universal 锁覆盖全平台全版本（uv 按 python 版本分叉选包），正好匹配"同一包不同 python 版本支持不同版本"的场景；
- 解析锁文件仅需非缩进 `name==version` 行，缩进注释行忽略；
- `download pypi` 的 `--python` 必填（uv 解析下限 + wheel 过滤）；包名带 `==版本`
  时锁定版本，裸包名经 uv universal 解析取兼容目标 Python 区间的最新版
  （多版本目标按 fork-strategy 自动分叉）；

### 5.3 PyPI 文件下载

- 对锁中每个 `name==version`：请求 `{源}/simple/{norm}/`（`Accept: application/vnd.pypi.simple.v1+json`，回退 HTML）；
- wheel 按目标 Python 版本（py3 通用 / cpN 精确 / abi3 向后兼容）与 `--platform`、`--arch`
  过滤平台标签；纯 Python wheel（any）与 sdist 不受过滤、始终保留；跳过 yanked；
- sha256 以 simple API 提供值为准，落盘 `{out}/pypi/{norm}/{filename}`。

### 5.4 CPython 安装包下载

- 元数据：`https://raw.githubusercontent.com/astral-sh/uv/main/crates/uv-python-managed/download-metadata.json`（uv 内置同一份，保证文件名/构建选择与内网 uv 请求严格一致；含全部历史 patch）；
- 过滤条件：`name == "cpython"`、非 prerelease、无构建变体（排除 freethreaded/debug）；
- `--python 3.12` 取该 minor 最新 patch；`3.12.4` 精确匹配；`--all-patches` 下载全部历史 patch；
- `--platform linux,windows` 按 `os` 过滤、`--arch x86_64,aarch64` 按 `arch.family`
  过滤（amd64/arm64 为别名），默认全平台全架构；
- 从条目 `url`（GitHub release 直链）下载，sha256 校验，落盘 `{out}/python/{build}/{filename}`。

### 5.5 产出下载产出目录

```
downloads/            # 默认固定目录；-o 可换
├── manifest.json
├── pypi/{norm}/{filename}
└── python/{tag}/{filename}
```

manifest.json：`{"version":1,"generator":"pkgmirror 版本","created":RFC3339,"files":[{"type","name/tag","filename","path","sha256","size"}]}`。
默认目录固定为 `downloads/`，重复下载时清单与已有条目**增量合并**（本次优先、
旧条目中磁盘仍存在的保留、文件已删除的剔除），不整体覆盖。下载失败即中止。

## 6. 客户端 upload

- 读 `{目录}/manifest.json`，逐条向 `{server}/api/upload` POST（Basic auth，凭据取 `--user/--pass` 或 URL 内嵌）；
- 服务端跳过已存在同哈希文件，幂等可重复执行；
- 结束打印汇总：新增 / 跳过 / 失败明细，失败非零退出码。

## 7. 验收与验证

- 单元测试：PEP 503 规范化、锁文件解析、wheel/sdist 文件名解析、simple JSON/HTML 双格式解析、元数据过滤（最新 patch/精确/变体排除/平台过滤）、上传路径校验（防穿越）、auth 中间件（含 401/凭据错误/恒定时间路径）；
- 集成冒烟（真实网络）：download 一个小包 + 一个平台受限的 python 版本 → 起 server → upload → curl 校验 `/simple/`、`/simple/{name}/`、`/python/{tag}/`、重复 upload 幂等；
- 交叉编译：linux/amd64、windows/amd64 构建通过（Win7 目标由 Go 1.20.7 保证）。

## 8. 构建与产物

`scripts/build.sh`（Linux/macOS）与 `scripts/build.bat`（Windows）交叉编译四个平台
产物到 `dist/`，并附带 `resources/` 下的两份示例配置：

- pkgmirror-windows-amd64.exe（Go 1.20.7 保证 Windows 7 可运行）
- pkgmirror-linux-amd64 / pkgmirror-linux-arm64（CGO 禁用，静态链接）
- pkgmirror-darwin-arm64

## 9. 风险与约束

1. **内网 uv 版本不宜过旧**：每个 minor 的新 patch 只被较新 uv 的内置元数据认识；旧 uv 请求新文件会 404。服务端 `/python/` 的 404 提示页引导补同步。内网统一 uv 版本即可规避。
2. **uv 元数据格式上游变更**：download-metadata.json 无版本化承诺，客户端解析失败时报错并提示升级 pkgmirror。
3. **同名不同内容**：上传 sha256 不一致返回 409，需人工删除旧文件，不自动覆盖。
4. **HTTP 明文**：内网环境可接受；凭据嵌 URL 会出现在 shell 历史，属内网工具常见取舍。
